# Sample dataset

The CSV files in this folder describe a fictional online retailer selling across six product
categories between 2023-01-01 and 2025-12-31. They are produced by
[`src/metricflow_platform/sample_data.py`](../../src/metricflow_platform/sample_data.py) with a fixed seed and can be
regenerated byte-for-byte:

```bash
python -m metricflow_platform generate-sample-data
```

The data is entirely synthetic. It does not describe any real company, customer or product, and it
contains no personal information. It is distributed under the repository's [MIT License](../../LICENSE).
Any figure computed from it describes the simulation only.

## Files

| File | Grain | Notes |
| --- | --- | --- |
| `customers.csv` | One row per customer | Signup date, location, acquisition channel, marketing opt-in |
| `products.csv` | One row per product | Category hierarchy, brand, launch and discontinuation dates |
| `product_price_history.csv` | One row per product price version | `valid_from` date with list price and unit cost; drives the SCD Type 2 product dimension |
| `orders.csv` | One row per order | UTC timestamp (ISO 8601), status (`completed` or `cancelled`), channel, payment method |
| `order_items.csv` | One row per order line | Quantity, unit price charged and line-level discount amount |
| `returns.csv` | One row per return | Returned quantity and refund amount per order line |

## Simulation characteristics

- Customer signups grow over time; about 15% of customers never place an order.
- Repeat-purchase probability and purchase frequency depend on the acquisition channel.
- Order volume follows a seasonal pattern that peaks in November and December, with heavier
  promotional discounting in those months.
- Products follow stable, growing or declining popularity trends; some are discontinued and others
  launch during the period.
- List prices and unit costs change roughly once a year, so the price charged depends on the order date.
- Returns depend on the product category and are only recorded when they fall inside the extract
  window, as a real extract taken on 2025-12-31 would.

## Intentional defects

To exercise ingestion validation against the shipped data, the generator appends these rows:

| File | Defect | Expected handling |
| --- | --- | --- |
| `customers.csv` | 3 exact duplicate rows | Deduplicated |
| `customers.csv` | `C99001` with an empty country | Rejected: required field missing |
| `customers.csv` | `C99002` with signup date `2024-02-30` | Rejected: invalid date |
| `orders.csv` | 5 exact duplicate rows | Deduplicated |
| `orders.csv` | `O999001`, `O999002` with unparseable timestamps | Rejected: invalid timestamp |
| `orders.csv` | `O999003` without a customer | Rejected: required field missing |
| `orders.csv` | `O999004` with status `pending_review` | Rejected: value not allowed |
| `order_items.csv` | 3 exact duplicate rows | Deduplicated |
| `order_items.csv` | `OI9999001` with quantity `two` | Rejected: invalid integer |
| `order_items.csv` | `OI9999002` with quantity `-1` | Rejected: below minimum |
| `order_items.csv` | `OI9999003` referencing a missing order | Rejected: orphaned foreign key |
| `order_items.csv` | `OI9999004` referencing a missing product | Rejected: orphaned foreign key |
| `order_items.csv` | A second version of `OI0000021` with a different quantity | Both versions rejected: conflicting duplicate key |
| `order_items.csv` | Final line with only three fields | Rejected: malformed row |
| `returns.csv` | `R999001` with an empty refund amount | Rejected: required field missing |
